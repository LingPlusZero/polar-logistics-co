# 精靈管理系統構想
每個部門至少要有1名正式/資深精靈、1名部長
3個實習生
1個副聖誕老人
刪除需要二次確認，自定義彈出視窗，不要用alert或confirm
後端分頁、篩選、排序，demo版的用前端模擬

## 簡易登入/登出
- 帳號：精靈編號、密碼：自定義
- 密碼規則，至少各一大小寫數字特殊符號
- demo帳號密碼驗證沒有意義，但我們可以檢查帳號是不是公司的精靈，權限依照精靈部門給

## 首頁
12/24 倒數計時
首頁可以活潑一點

## 選單
fixed在左側，右側顯示頁面內容
依照權限判斷要不要顯示
- 請假
  - 請假申請
  - 請假審核
- 精靈管理
  - 精靈請假紀錄
  - 精靈被申訴紀錄
  - 精靈出勤紀錄
- 動力單位管理
- 職缺管理

## 修改密碼
- 權限：所有人
- 舊密碼、新密碼、再確認一次新密碼

## 精靈名冊
- 權限：人力資源部
- 搜尋：精靈編號/姓名模糊搜尋、部門篩選
- 排序：依年資、部門、精靈編號
- 狀態(正常/請假/可能失蹤)、姓名、部門、職稱、精靈編號、到職日期、年資、備註
- 新增、修改、刪除
- 不可修改欄位：精靈編號、到職日期、年資
- 精靈編號新增時由系統自動產生
- 狀態「請假」由請假單決定（有申請且正在假期內才顯示），不能手動修改
- 預設資料有 4 位「可能失蹤」的精靈，備註如下：
  - E010 蕨影（禮物包裝部）：疑似在包裝區被誤包進禮物，目前已確認 3 號輸送帶上有一個會說話的禮物盒，尚待拆封確認；拆封前請勿搖晃
  - E012 岩薔（外勤機動部）：最後一次回報位置為「某戶人家的煙囪內」，預計下一次回報時間不明
  - E015 霜華（乖寶寶稽核部）：自上次稽核起未回報，疑似仍在觀察某位孩子是否真的乖
  - E018 冰晶（運輸部）：最後出勤紀錄為雪橇維修站，之後下落不明，雪橇備用鑰匙一併失蹤

## 精靈請假紀錄
- 權限：人力資源部
- 精靈編號、申請日期、假別、審核日期、審核結果(核准/駁回/審核中)

## 精靈被申訴紀錄
- 權限：人力資源部
- 精靈編號、投訴日期、投訴事由、後續處理

## 精靈出勤紀錄
- 權限：人力資源部
- 精靈編號、上班時間、下班時間

## 動力單位管理
- 權限：人力資源部、馴鹿管理部
- 目前只有9隻馴鹿，所以不用搜尋
- 排序：依年資、部門、編號
- 姓名、編號、到職日期、年資、上次保養日期、下次保養日期(間隔3個月)、照護專員、備註
- 每列有幾個按鈕可以打開/關閉子table：
  - 請假記錄：申請日期、假別、審核日期、審核結果(核准/駁回/審核中)、駁回理由
  - (被)申訴紀錄：投訴日期、投訴事由、後續處理
  - (近一週)出勤紀錄：出勤時間
- 07的備註會寫問題單位不擅與人合作(已經讓3人離職)
- 新增、修改、刪除
- 不可修改欄位：編號、到職日期、年資、下次保養日期(自動算)

## 請假申請/審核
- 權限：所有人
- 假別：普通病假(1天)、魔力枯竭假(2天)、被人類目擊後心理創傷假(7天)
- 審核權限：部長審核部門的精靈假單(包含實習生)、副聖誕老人審核各部長假單
- 每個假不能重疊
- 旺季(12月)不能請假，畫面會顯示文字叫大家撐下去
- 馴鹿要請假需要請他的照護專員代請，所以照護專員會有選項勾選要幫自己請假還是馴鹿

## 職缺管理 (官網上顯示)
- 權限：人力資源部
- 職缺名稱、職缺部門(下拉選單)、工作內容、任職資格、福利、備註
- 新增、修改、刪除
